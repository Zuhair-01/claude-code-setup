## Runtime gotchas (verified on this machine)
- **Machine Python is 3.14** → mediapipe/ctranslate2/faster-whisper have NO 3.14 wheels. MUST use a **3.12 venv via uv** (`uv python install 3.12`; `uv venv --python 3.12 .venv`). uv is v0.5.9 installed.
- **uv pip install is atomic** — a single network reset wipes all progress. On flaky network use **pip inside the venv** (`ensurepip` first; uv venvs have no pip) — pip resumes from cache.
- FFmpeg 8.1.1 present with `h264_nvenc`, `libx264`, `libass`. GPU: RTX 4060 Laptop, 8GB VRAM.
- **Ollama installed models: `gemma4:latest`, `deepseek-r1:8b`, `qwen2.5-coder:7b`** — NOT llama3.1/mistral. Scorer auto-detects installed models via `/api/tags` and falls back to heuristic-only if none/down. Default pref still `llama3.1:8b` (pull it or set `OLLAMA_MODEL`).
- GateGuard hook (ecc plugin) fact-forces every Edit/Write and first Bash — disable per-session with `ECC_GATEGUARD=off` if it slows a big build. Writing files via Bash heredocs bypasses the edit/write gate.
- **`faster-whisper` first load can hang for minutes** even with the model already cached (`~/.cache/huggingface`) — `huggingface_hub` does an online freshness check by default and this machine's network is flaky. Run the API with `HF_HUB_OFFLINE=1`.
- **CUDA/cuBLAS**: `ctranslate2.get_cuda_device_count() > 0` only confirms a device exists, not that cuBLAS (`cublas64_12.dll`) is loadable. Root cause found 2026-07-17: the CUDA-12 runtime wheels weren't installed AND Windows never had `site-packages/nvidia/*/bin` on its DLL search path. FIX (`7674ccb`): `_register_cuda_dll_dirs()` in transcribe.py + `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12==9.*` into `.venv`. transcribe.py still CPU-falls-back on any load failure (keep that safety net).
